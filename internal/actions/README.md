# Owner-local actions

Registration: `actions.RegisterTools(registry, db.Actions())`. The host supplies the authenticated owner, agent and persisted run; none is a model argument. “Public” means shared between this owner's authorized agents, **not** across users. There is no external push adapter, delivery status, or implicit worker goroutine.

| Tools | Permission | Meaning |
|---|---|---|
| `public_todo_upsert`, `public_todo_complete` | `todo.write` | Stable `todo_key` identifies a task across channels. A new `idempotency_key` permits a deadline/title revision. Omitted deadline/body preserves existing values; revisions don't reopen completed tasks. |
| `public_todo_list` | `todo.read` | Owner-scoped public todos, including completed ones. |
| `notice_create`, `notice_list` | `notice.write`, `notice.read` respectively | `mode=active/silent` is a local presentation choice by the model. Provide evidence and reason. Omitting `due_at` records immediately; specifying it creates a planned Notice. |
| `planned_job_create`, `planned_job_cancel`, `planned_job_list` | `job.write`, `job.write`, `job.read` respectively | Notice, allowlisted ToolCall, or Worker self-run only. Cancellation is idempotent for cancelled jobs, and refused for running/completed jobs. |

All mutations return `kind/id/status` plus persisted fields; lists return `items`, limit 1–100 and offset up to 100000. Action IDs can be read with `GetAction(ctx, owner, kind, id)`. Same owner/request key and JSON content return the same entity (its **current** state); different content with the same request key is a conflict, not a second mutation. Use the same `reminder_key` across channels for the same reminder even when the request keys differ. With the same reminder identity, timing and mode, prose changes alone do not fire again. Changed timing or mode supersedes a pending occurrence atomically. A running occurrence cannot be superseded. If no explicit reminder key is provided, the request key serves as its identity; no fuzzy text matching is performed.

Active notices require `intent_turn_id` (actual authenticated owner message/answer), `intent_quote` (verbatim instruction), and `reason`. Importance or an automated event alone is insufficient: use silent if no instruction applies. Recurring active notices additionally require `preference_memory_id`: personal, current, active, visible in this run's agent/workflow/public scope, with `source_refs` containing `chat_turn:<turn ID>` or `question_answer:<ChA/ChB question ID>`. For either continuation channel, pass the raw persisted question ID as `intent_turn_id` and quote the owner's answer (not the generated question or its options). Only a claimed running/completed answer with a matching stored SHA-256 qualifies. The database checks the turn quotation and any referenced memory at creation and again at firing. A changed/expired/archived preference cancels the occurrence without recording a notice or creating a successor. The checks establish provenance and currency, not semantic entailment; the model is responsible for selecting a genuinely applicable instruction. Generic `evidence` entries are citations, not independently certified facts. The trusted host pins the actual source run and agent. ChA continuation can call `RecordQuestionNotice` in its own transaction; the resulting notice is silent and mentions the persisted question.

The host explicitly calls `Executor.RunOne(ctx)`. It claims at most one due job and re-reads the creator's current status, enabled tools, and permissions. A Notice records the local entry and completes the occurrence together; no model or delivery step. The ToolCall allowlist is `schedule_get` (`{id}` via typed host callback), `public_todo_list` and `notice_list` (`{}`; save first 20 id/kind/title/status projections in the job), `public_todo_upsert` (`{todo_key,title,body?,due_at?}`; inherits job evidence and a reserved per-occurrence request key), and `public_todo_complete` (`{id}`; idempotent). Both deferred writes require the target tool and current `todo.write`; they return a receipt from the actual owner-scoped mutation. Worker jobs run only the originating enabled Worker agent via typed host callback and save the actual new run reference. Callbacks must check their own scoped targets and report failures truthfully. No tool can send arbitrary Bridge operations, select an owner/agent target, invoke shell or schedule arbitrary tool writes. Optional `repeat_weekly=true` and IANA `timezone` preserve local weekday and wall time; missed weeks and DST gaps are skipped. A successful occurrence and its next pending occurrence commit together. A process crash after claim may leave `running`; it is intentionally not replayed automatically, since external execution of a self-run may be ambiguous. Investigate the real run before rescheduling.

Schema: v18 appends owner-scoped `public_actions`, `action_receipts`, `reminder_keys` alongside continuation/chat storage. Test fixtures use random schemas only under an explicitly supplied temporary `TEST_DATABASE_URL`. No production DB or frontend changes are part of this package.
