# 计划任务

后台入口 `/admin/tasks`，从用户后台和 Agent 控制台均可进入。复用管理员登录和现有 CSRF 中间件。

页面现以“逐项处理、运行现场、生成结果、采集与批次”组织：按当前轮次读取 `/api/v1/control/items` 与 `/artifacts`，展示每项状态、处理依据、实际路由以及通知/记忆/工作流/总结等可读卡片。事项进度使用服务端返回的叶子计数，原文容器不会重复计数；处理进度计入所有终态，业务完成/忽略与需要关注分别统计。Workflow按真实entity_ref分组，区分独立流程与创建、更新、复用记录；回读数据标为当前版本。TASK/RESOURCE的引用只表示来源记录，不暗示存在独立Task库。前500项每2秒更新，继续加载更多后的扩展列表保留快照并提示手动刷新；运行现场仍持续更新。通知生成与外部送达明确分开，产物中无送达记录时不声称已发送。详情展示来源信息、子运行轨迹、操作及结果，原始JSON只在折叠的开发者数据中保留。旧服务没有逐项/产物接口时回退到总览并明确提示，不生成伪造结果。

学习通 / MOOC 的同课程变化统一交给 Trigger 初筛；批次行和详情展示后端提供的课程名称，教学实例、来源连接与平台课程引用作为辅助信息。后端明确标记 `scope.kind=unassociated` 时显示“未关联课程”，不从变化内容猜测课程。历史批次未提供 `scope` 时保留平台展示。新DWS批次按同轮用户＋连接＋群封批，页面显示群标识及连接；群归属无法确认时显示“群归属待核查”，该事件封为blocked。单群超限才在群内拆块，不与其他群拼批。U校园沿用现有分批。连接、群与教学实例标识保留原值，便于区分同名对象。

当前仅一个全局 `information-refresh` 时钟，启动时扫描一次，此后每轮完成后等待默认10分钟。每轮依次调用学习平台 `Poll`（学习通、MOOC、U校园）和 DWS `Poll`；教务系统保持手动采集。连接仍由 Repository 筛选已登录、启用且用户未停用的目标。平台分页、DWS 授权群、水位和数据隔离沿用现有实现。

APP 显式启动并等待此 Worker 结束，scheduler 不创建隐式 goroutine。DWS Run 继续处理手动任务和设备授权生命周期；DWS 定时扫描与队列消费通过 workerMu 串行，原有连接租约仍生效。学习平台 Run 仅负责取消时释放认证资源，独立计时器已移除。

| 接口 | 行为 |
| --- | --- |
| GET `/api/v1/tasks` | 列表、间隔、暂停/运行/排队状态、下一次时间、最近开始/完成时间、轮数、安全错误 |
| PUT `/api/v1/tasks/{id}` | body `{enabled:boolean, interval_seconds:60..86400}`，更新当前进程设置 |
| POST `/api/v1/tasks/{id}/trigger` | 排队一轮，返回202；正在执行或已经排队返回409 |

手动触发不受暂停限制，暂停不终止已运行扫描。任何修改与重复触发都不会让同一轮并发执行。202仅表示请求已接受；完成后查看 last_finished 和 last_error，具体失败连接/资源仍在原抓取状态查看。某资源失败会继续尝试其他资源，整轮标记部分失败；没有目标时扫描可正常完成。

运行调整是全局且仅当前进程有效，重启恢复部署配置。新环境变量 `REFRESH_INTERVAL=10m` 统一配置时钟；兼容 `DWS_POLL_INTERVAL`，前者优先，旧变量现在也作用于整个信息刷新周期。服务均未配置时列表为空。预览接口的两项间隔字段均读取共享时钟当前值，暂停和执行状态以计划任务为准。页面不定时访问上游，只通过“刷新任务状态”读本地状态。

测试：`go test -race ./internal/scheduler ./internal/app ./internal/platform ./internal/dws ./internal/preview`，覆盖暂停/恢复、手动触发去重、运行中不重入、截止与退出、管理员权限、输入校验和间隔配置。测试使用假回调，不代表真实平台采集成功。

本地批测：在 backend 目录加载 `.env` 后执行 `python3 scripts/scheduler_regression.py`，会临时改间隔、暂停共享任务并实际触发一轮全部平台刷新，最后还原设置和清理临时用户。202、计时器控制通过不代表全部上游同步成功，报告单独记录 manual_round.last_error。

2026-11-04 验证：后端全包 `go test -race ./...`、`go vet ./...` 通过；未设置 TEST_DATABASE_URL，数据库集成测试按现有机制跳过。运行中接口批测17项通过，实际手动扫描完成但报告部分连接同步失败。浏览器验证导航、暂停/恢复、间隔修改与还原、桌面/移动页面，无脚本异常。接口报告 `.build/scheduler-regression.json`，截图 `.build/scheduler-desktop.png` 与 `.build/scheduler-mobile.png`。

每轮新增按来源的 `results` 统计：连接数、尝试/成功/失败数、新增/更新/相同内容条数和安全错误码；`history` 保留当前进程最近10轮。运行中显示当前进度，结束后保存该轮快照。记录计数仅在数据库事务提交成功后增加，回滚不计数；相同内容表示本轮重新观察到的同哈希记录，不等于全部归档总量。统计限定本轮调度上下文，不混入独立手动同步。没有连接、未配置服务、没有采集资源分别展示；DWS 没有资源特指采集群白名单为空。连接列表仅显示启用连接，断开后的归档仍保留。

2026-11-04 补充验证：统计实现通过设置独立 PostgreSQL TEST_DATABASE_URL 的全包 race 测试和 vet；接口批测18项通过。此前六个连接已断开，随后创建的学习通、MOOC、U校园和 DWS 四个连接按用户要求保留。真实平台结果仍需分别查看，接口测试通过不代表没有上游失败。

本次实际诊断：学习通部分课程请求从 `/visit/stucoursemiddle` 重定向到 `/antispiderShowVerify.ac` 并返回202，需要在官方平台处理验证；MOOC 的目录子集合 `units:null` 导致本地解析失败，已兼容可空子集合并保留根目录/畸形字段校验；U校园扫码授权不含教材内容会话，作业/进度返回 unsupported；DWS 已连接但授权采集群列表为空，尚未发起消息采集。没有自动扩大群授权范围。

批量诊断工具：加载与服务相同的环境后运行 `go run ./cmd/refresh-probe`，或 `PROBE_SOURCE=mooc go run ./cmd/refresh-probe` 限定来源。工具通过正常 Service 同步路径读取上游并更新本地归档/检查点，仅记录 HTTP 路径、状态、字节数和固定字段的结构计数，不输出请求参数、Cookie、密钥或响应正文；不要与同连接的其他手动同步并发运行。

后续学习通诊断已修正上段处理结论：202验证页的本账号触发因素是回放旧 `k8s`，单因素对照已确认；适配器现忽略持久化旧票、保留当前流程新票，批量访问不再出现验证码。遇真正验证/429时停止该连接本轮后续资源和讨论课程，结果保留 `verification_required` / `rate_limited`，其他连接继续。仍采用默认10分钟刷新周期。
