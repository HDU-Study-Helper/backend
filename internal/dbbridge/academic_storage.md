# Academic projection storage (v12–v13)

## MOOC course structure audit (2026-11-11)

MOOC reply observations use `discussion_reply_user` with an empty body, explicit topic ID and source-term/course evidence. They are persisted with the discussion checkpoint but do not create independent control events or work items; the root discussion carries roster coverage. Legacy roster course references can resolve through an exact archived parent topic, never a matching title. Reply timestamps and explicit zero/false participation state remain queryable. Plain contentType6 compatibility never changes a progress or roster record into a discussion.

Offerings retain up to two bounded `details.catalog_sources` snapshots for the owner route and referenced source term, including independent descriptions, teaching names, catalog counts and time evidence. Source metadata is not inherited when a DTO omits fields. Personal-state projection preserves native submission/evaluation values, `totalLearnedTime` and progress/participation counters without interpreting unknown enums. Agent queries expose these through explicit fields or sanitized metadata. The academic directory keys chapter/lesson containers by offering, source term and native identity; every item appears once, and reply rosters group by exact topic and load collapsed.

## Detailed collection and keyword profiles (2026-11-09)

Chaoxing assignment header evidence retains answer-window start/end/deadline, question count and full score without inferring a year. Native teaching nodes retain paths, per-node task-point counts and explicit personal markers; title-only groups remain path labels. Discussion reply observations retain source timestamps and verified current-user comparison when available; absence from an incomplete list is not non-submission. MOOC preserves independent assessment/peer-review/score-publication fields, native progress semantics and bounded discussion reply coverage. Nested metadata is reconstructed only from explicit scalar key whitelists before Agent exposure.

Agent data now includes owner-scoped active `schedules`, authorized-group `dws_messages` and archived `dws_attachments` metadata alongside the platform and academic datasets. `data_search` performs a case-insensitive literal OR union across keyword values and datasets, with owner/query-bound keyset cursors and per-dataset coverage. It returns bounded discovery summaries; complete fields remain available through `data_query`. Query pagination includes explicit `has_more` and `next_offset`. Search pages observe current data, not an immutable multi-request snapshot.

`workflow_create.initial_private_memories` atomically creates a Workflow, its first version and source-linked PRI memories. The server assigns the new Workflow ownership; ordinary unbound memory ACLs remain unchanged. The receipt contains persisted memory IDs and a content digest only after commit. Optional profile_manifest metadata is checked only for object shape. Investigation scope, pagination, dataset choice, topic organization and whether evidence is sufficient belong to the Learner; neither creation nor handoff requires coverage, a prescribed index or a fixed set of topics. Handoff still reads the persisted Workflow and verifies its owner, entity, active state and version.


`DB.Academic()` implements `model.AcademicRepository`. Migration v12 creates the native `courses` catalog, teaching-class/term `academic_offerings`, `academic_items`, record-level `academic_item_evidence`, and separate `academic_item_personal_states`. Every relationship includes owner and connection in its foreign key. Additive v13 retains readable course descriptions and bounded details (requirements, goals, target audience, workload, style, source course name, and teacher names) on offerings. Previously applied v12 remains unchanged. SQL remains in dbbridge.

Run the existing explicit `DB.Migrate(ctx)` first. Migration only creates projection storage; it does not collect upstream data or rebuild existing raw records. `Academic().Rebuild(ctx, owner, source)` explicitly rebuilds enabled, active chaoxing/mooc connections for that owner, in one transaction. Empty source means both supported sources. A disabled owner is rejected. Raw `platform_records`, source credentials, cursors, and record counts remain unchanged. Repeating a rebuild preserves deterministic IDs and does not rewrite identical projection rows. Reconciliation deletes derived rows only when unsupported by the current raw authority; upstream absence on one page is not a deletion.

The platform commit integration calls `syncAcademicConnection(ctx, tx, owner, connection)` after raw upserts and before checkpoint/session commit. Other sources return immediately. Any projection error rolls back the raw page and checkpoint as well. Projection writes use one pgx batch per connection reconciliation, preserving foreign-key order while avoiding individual network round trips per statement. The current implementation scans that connection's archived records and reconciles all its projection rows per page; this favors a simple correct transaction over an incremental dependency graph and may require optimization for much larger archives.

Courses bind through explicit course/class or course/owner-term fields and known course ParentID references. Matching titles never bind a course. SPOC source terms remain reference relations and cannot replace the owner's term. Native opaque JSON/base64 identifiers are retained. Legacy five-component MOOC unit keys normalize to the newer six-component key only for their explicit source term or original owner term; a previously unknown reference term is not guessed. Task/progress observations sharing a native identity become one item with multiple evidence IDs. Last-visited-unit observations remain separate course observations. Plain legacy MOOC contentType 6 units without explicit assessment evidence normalize to discussions; historical raw JSON stays unchanged and the reason appears in projected metadata.

Time columns contain queryable timestamps with corresponding AcademicTime JSON for value, raw text, precision, source field, and missing/partial state. Local explicit timestamps use Asia/Shanghai. Day-only values retain Date=YYYY-MM-DD with precision day and no instant, so a deadline never becomes fabricated midnight. Yearless dates retain partial precision without guessing a year. Reversed exam ranges retain raw endpoints as partial evidence and clear both sortable instants. Exam ranges populate start/end independently of publication. Ambiguous material `time_raw` remains metadata `unclassified_time`, without assigning created/updated semantics. Collection time never fills publication. Unknown status codes, scores, and attempt counts do not establish completion. Personal score, attempt, evaluation, and progress fields live separately from content evidence. Metadata and nested coverage use explicit bounded whitelists; generic source maps and credentials are not copied.

Offerings/Items queries scope every row to owner and enabled active connections. Optional filters include source, connection, offering, opaque course reference, kind/status/text and publication/deadline ranges. Limit defaults to 20 and allows up to 101 for caller pagination. Tree uses a repeatable-read snapshot and accepts optional source/connection filters; it returns all archived items and offerings within its 20000-row bound per collection or fails with `ErrAcademicTreeOverflow` wrapping `model.ErrConflict`. It never silently truncates or asserts complete upstream collection. Offering coverage separates normalized logical `item_count` from raw-category `evidence_record_count`; legacy `record_count` retains the raw count for compatibility. Route and active source-term relations remain distinct. Late progress updates personal state and reliable explicit times without overwriting collected content metadata; newer authoritative read-empty bodies and observed missing deadlines do not resurrect older raw evidence.

Validation commands: `env -u TEST_DATABASE_URL go test ./internal/dbbridge` and `env -u TEST_DATABASE_URL go vet ./internal/dbbridge`. Default tests do not access PostgreSQL or upstream sources. With an explicitly supplied dedicated TEST_DATABASE_URL, existing `testDB` creates/removes a random schema. Academic integration tests exercise migration, rebuild idempotency, evidence/class/owner isolation, course/time/text filters, stale reconciliation, active connection visibility, preservation of raw/credentials, and raw-page rollback when projection fails. Date and projection unit tests cover partial dates, epochs/ranges, legacy classification, progress merging, and metadata safety.
